# 多言語表示（日本語／英語）

利用者向け画面（`index.html`・`servicestatus.html`・`howto.html`）は日本語と英語で表示できる。管理画面（`admin.html`）は日本語のみ。

## 言語の決まり方

`frontend/i18n.js` が読み込み時に1回だけ決める。

1. URL の `?lang=ja` / `?lang=en`（指定されたら localStorage `busTimeLang` にも保存する）
2. 保存済みの選択（localStorage `busTimeLang`）
3. ブラウザの言語（`navigator.languages[0]`）が日本語なら日本語、それ以外は英語

ヘッダーの言語切替ボタン（日本語表示では「🌐 EN」、英語表示では「日本語」）とチュートリアル1枚目のボタンで切り替える。切り替えは選択を保存してページを読み直す（描画済みの全画面を確実に新しい言語で描き直すため）。`<html lang>` も合わせて書き換える。

## 2種類の訳

### 画面の文言（UI文字列）

- 日本語の文言そのものをキーにして `t('バス停')` のように引く。辞書は `frontend/i18n-en.js`。
- 差し込みは `t('{n}分遅れ', { n: 5 })`（キー側にも `{n}` を書く）。英語の単複など語形が変わるものは、辞書の値を関数にする。
- HTMLに名前（`nameHtml()`の結果）を差し込むときは `I18n.tHtml()` を使う（文言はエスケープし、差し込む値はHTMLのまま入れる）。
- 静的HTMLの文言は `I18n.translateStatic()` が、テキストノード（前後の空白を除いた中身）と `title`/`placeholder`/`aria-label`/`alt` 属性を辞書で引いて置き換える。
- **辞書に無い文言は日本語のまま出る**（画面は壊れない）。日本語の文言を変えたら、`i18n-en.js` のキーも同じ文字列に直すこと。
- サーバーが返す定型文（運行区分ラベル「平日」、支払い方法、経路検索の注記・エラーなど）も同じ辞書で訳す。経路検索の「見つからない」理由はバス停名や時刻が埋め込まれているため、`routesearch.js` の `notFoundMessage()` が `reason` ごとに組み立て直す。

### 固有名詞（バス停名・路線名・行き先・事業者名）

APIは日本語名のまま返し、画面側で `GET /api/i18n/names?lang=en` の名称辞書を引く（`I18n.name()` / `nameHtml()` / `nameText()`）。英語表示では名称辞書の到着を待ってから最初の画面を描く（上限4秒。超えたら日本語名のまま描く）。

名称辞書は `backend/src/services/nameTranslations.js` が、有効な全GTFSフィードの `translations.txt`（任意ファイル）から作る。表示名は次の順に決める。

1. 表示言語そのものの訳（`language=en`） … source `gtfs`
2. ローマ字表記（`language=ja-Latn`） … source `romaji`
3. かな（`language=ja-Hrkt`）をヘボン式でローマ字にしたもの … source `romaji`
4. いずれも無ければ辞書に載せない（＝**日本語のまま表示**）

- 対象は `stops.stop_name`・`routes.route_long_name`/`route_short_name`・`trips.trip_headsign`・`stop_times.stop_headsign`・`agency.agency_name`。現行書式（`table_name`/`field_name`/`language`/`translation`/`record_id`/`field_value`）とGTFS-JP旧書式（`trans_id`/`lang`/`translation`）の両方を読む。言語タグが空の行は、中身がかなだけならかな、ラテン文字を含めばローマ字とみなす。
- 辞書のキーは日本語名そのもの。リアルタイム系（DBの`stops.name`/`routes.name`）も時刻表系（GTFSインメモリインデックス）もGTFSの名前文字列を返すため、名前で引けばAPIのレスポンス形を変えずに全画面で同じ訳が使える。
- 行き先は `headsigns` → `stops` の順に引く（行き先はたいていバス停名）。「◯◯経由△△」「△△行き」「◯◯（△△）」「◯◯・△△」「◯◯-△△」のように組み立てられた名前は、部品ごとに訳して組み直す（訳せなかった部品は日本語のまま）。
- キャッシュはプロセス内（30分TTL）。GTFS更新成功時（`gtfsFeedManager`・管理画面の手動再取得）に `invalidateNameTranslations()` で破棄する。

**英語表示で名前を訳したときは、必ず日本語表記を併記する**（バス停・車内の案内表示は日本語のため）。`nameHtml()` は訳の後ろに `<span class="i18n-ja">日本語</span>` を付け、`nameText()` は「表示名 (日本語)」の形にする。訳した名前を含む `.truncate` の行は、英語表示のときだけ折り返して全部見せる（`style.css`）。

### 観光スポット

- 名前：「ローマ字」列（空欄ならかなから自動生成）＋日本語の名称を併記（`I18n.spotName()`）。ローマ字が無ければ日本語の名称のまま。
- 営業時間・滞在目安・説明：英語版（`hours_en`等）があればそれ、無ければ日本語版（`I18n.spotField()`）。詳細は [tourist-spots.md](tourist-spots.md)。
- タグは訳さない（予約タグ「近い」の表示だけ "Nearby"。値は日本語のまま）。

## 訳さないもの

- 管理画面で入力するお知らせ（トップ・路線・バス停）の題名・本文、リアルタイム休止の理由。
- 路線バス運行状況（アルピコ交通公式サイトから取得した本文）。英語表示ではその旨を注記する。
- お気に入りルートに利用者が付けた名前。
- 表示略称（管理画面「表示略称設定」）は日本語の系統名・行き先に対するものなので、英語表示では使わない（`text-abbrev.js`）。

## お気に入り

保存する `title`/`subtitle` は表示言語によらず日本語。組み立てた題名（「◯◯ 行」「路線・時刻発」「出発地 → 目的地」）は、英語表示用の組み立て方を `titleI18n`/`subtitleI18n` に一緒に保存する（`favorites.js` 冒頭のコメント参照）。これが無い古いお気に入りは、題名を固有名詞として、副題をUI文言として訳せるだけ訳す。
