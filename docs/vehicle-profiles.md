# 車両詳細情報（公開用：バスアイコン・設備・お支払い方法）

車両ID（`car_id`）ごとに、**利用者向け画面に出す**車両の情報を登録する機能です。

- バスアイコン（車両の外観画像）
- ノンステップバスか
- 車いす対応か
- お支払い方法（選択式）＋補足（自由記述）

管理画面「車両詳細情報（公開）」（`frontend/admin-vehicle-profiles.js`）で編集し、`vehicle_profiles`テーブルに保存します。サーバー側の処理は`backend/src/services/vehicleProfiles.js`にまとめてあります。

## 「車両名・メモ管理」との違い

| | 車両名・メモ（`vehicle_labels`） | 車両詳細情報（`vehicle_profiles`） |
|---|---|---|
| 用途 | 運用者が車両を識別するための名前・運用メモ | 利用者に見せる車両の外観・設備・お支払い方法 |
| 公開 | **しない**（管理画面だけ） | **する**（利用者向け画面にそのまま出る） |
| 管理画面 | 車両名・メモ管理 | 車両詳細情報（公開） |

**2つのテーブルを統合したり、片方の値をもう片方の画面へ流用したりしないでください。** 統合すると、運用メモが公開APIに漏れる、あるいは公開情報の編集で管理用の名前が消える、という事故につながります。キーはどちらも`car_id`（1事業者内では`car_id`が物理車両を一意に指す）です。管理画面では、編集対象の車両を**車両名でも検索できる**ようにし（後述）、一覧にも識別の補助として管理用の車両名を併記しますが、公開APIには載せません。

## 編集対象の車両の探し方

入力欄は車両IDと車両名（`vehicle_labels.name`）の両方を部分一致で検索します（全角・半角、大文字・小文字、空白の違いは無視）。候補は「最近観測された車両」「車両名を登録した車両」「車両詳細情報を登録した車両」の和集合です。

候補を選ばずに入力した場合は、保存時に**車両IDとして完全一致 → 車両名として完全一致 → 入力値をそのまま新しい車両ID**の順に解決します。車両IDを優先するのは、ある車両の名前が別の車両のIDと同じ文字列でも取り違えないためです。この解決が1台に定まるよう、**車両名は重複不可**にしてあります（`vehicle_labels`の部分一意索引`ux_vehicle_labels_name`、`PUT /api/admin/vehicle-labels/:carId`は重複時に409）。既に登録のある車両に一致したときは、その登録内容をフォームに読み込みます（空のフォームで上書き保存する事故を防ぐため）。

## バスアイコン

- 選択肢は**コードに列挙せず**、`frontend/images/`に置かれた画像ファイル（`.png`/`.jpg`/`.jpeg`/`.webp`/`.gif`/`.svg`）をそのまま使います。**画像ファイルを置くだけで管理画面の選択肢に増えます**（コードの変更・再起動は不要）。
- DBにはファイル名だけを保存し、URL（`/images/<ファイル名>`）は読み出し時に組み立てます。
- 保存時（`normalizeVehicleProfileInput()`）に、ファイルが実在するかを検証します。存在しないファイル名・パスを含む指定は拒否します。
- 公開APIでの読み出し時にも実在を確認し、**画像ファイルが消えていれば`iconUrl: null`（＝未設定扱い）にします**。利用者画面に画像のリンク切れを出さないためです。ディレクトリの一覧は60秒キャッシュするため、画像を消してから反映されるまで最大60秒かかります。管理画面の一覧では「画像なし」と表示されます。
- 画像は表示枠に収まるよう縮小（`object-fit: contain`）して表示します。**画像の余白はトリミングされないため、余白が大きい画像は小さく見えます。** 車両が画像いっぱいに描かれた画像を置いてください。

## お支払い方法

選択肢は`vehicleProfiles.js`の`PAYMENT_METHODS`（現金・交通系ICカード・クレジットカードのタッチ決済・QRコード決済）です。DBにはキーの配列（`payment_methods TEXT[]`）を保存し、表示ラベルは公開APIが付けて返します（フロントエンドは選択肢の定義を持ちません）。選択肢を増やすときは`PAYMENT_METHODS`に足すだけです。定義から消したキーがDBに残っていても、公開APIは無視します。選択肢に無い支払い手段・条件は「お支払い方法の補足」（200文字以内）に書きます。

## ノンステップ・車いす対応

`TRUE`（対応）・`FALSE`（非対応）・`NULL`（未登録）の3値です。**未登録の項目は利用者画面に出しません**（「非対応」と「情報が無い」を区別するため）。

すべての項目が未設定の状態で保存すると、行を削除します。

## 利用者向け画面での表示

公開APIのバス情報（`/api/buses`の各要素、`/api/buses-for-map`の各要素、`/api/timetable/trips/.../realtime`の`bus`）に`vehicleProfile`を載せます。未登録の車両は`null`です。

```json
"vehicleProfile": {
  "iconUrl": "/images/alpicobus.png",
  "nonStep": true,
  "wheelchair": null,
  "paymentMethods": [{ "key": "cash", "label": "現金" }],
  "paymentNote": ""
}
```

描画は`frontend/vehicle-info.js`（`window.VehicleInfo`）に一本化してあり、`app.js`・`realtime-diagram.js`・`timetable.js`より先に読み込みます。バスアイコンが未登録（または画像が消えた）車両は、各画面とも従来のアイコン（🚌等）のままです。

| 画面 | 使い方 |
|---|---|
| リアルタイム時刻表（カード表示、`app.js`の`createBusCard`） | バスカード左のアイコンを画像に置き換え |
| リアルタイム時刻表（基本表示、`realtime-diagram.js`の`iconRowHtml`） | リアルタイム便のアイコンを画像に置き換え（時刻表推定便は車両が分からないため対象外） |
| バスマップ（`app.js`の`createBusIcon`） | 背景・枠を付けず画像だけをマーカーにする（路線カラーは下のラベルで示す。透過PNGを前提とし、画像に塗られた背景はそのまま出る。44×32px、`style.css`の`.bus-marker-photo`） |
| 便詳細ページ（リアルタイム表示、`timetable.js`） | 「車両詳細」ボタン → ポップアップ（`#vehicle-detail-modal`）で画像・設備・お支払い方法を表示。「地図で表示」の車両マーカーも画像にする |

「車両詳細」ボタンは、**表示中の便を走っている車両に登録があるときだけ**出します（未登録の車両でボタンを出しても「情報がありません」としか表示できないため）。

## 地図上の向き（進行方向）

登録する画像は**すべて左向きの横顔**である前提です。地図（北が上）では進行方向に合わせて向きを変えます。

- サーバー（`services/vehicleHeading.js`の`getVehicleHeadings()`）が進行方向の方位角`heading`（度。真北=0・東=90・時計回り。算出できなければ`null`）を求め、`/api/buses-for-map`の各バスと`/api/timetable/trips/.../realtime`の`bus`に載せます。対象はバスアイコンを登録した車両だけです（🚌の丸アイコンは向きを使わないため、算出のクエリを省く）。
  1. **走行軌跡**：最新の測位と、直近5分以内で20m以上離れたいちばん新しい測位を結んだ向き。20mのしきいは、停車中のGPSの揺らぎで向きが暴れないようにするためです。
  2. **次のバス停**：走行軌跡が取れない（停車中・始発で発車待ち等）ときは、最後に到着したバス停より先のバス停のうち、現在地から30m以上離れた最初のものへの向き。
  3. どちらも取れなければ`null`（画像のまま左向き）。取得に失敗した場合も空のMap（全車両そのままの向き）を返すsoft-failです。
- フロント（`vehicle-info.js`の`markerTransform()`）が方位角どおりの向きに画像を変形します（斜め方向もその角度へ向ける）。**回転角は常に±90°以内に収め、車体が逆さまにならないようにします。**

| 方位角 | 変形 | 例 |
|---|---|---|
| 180°〜360°（西寄り。真北0°を含む） | 反転せず、時計回りに（方位角−270）°回転 | 北西315°→時計回りに45°、真北→時計回りに90°、真南→反時計回りに90° |
| 0°〜180°（東寄り。両端を除く） | 左右反転してから、時計回りに（方位角−90）°回転 | 北東45°→反転して反時計回りに45°、真東→反転のみ、南東135°→反転して時計回りに45° |

CSSの`transform`は右の関数から先に効くので、`rotate(θ) scaleX(-1)`＝反転してから回転です。画像要素は常に44×32pxで、マーカーの枠（と`L.divIcon`の`iconSize`）は回転後の外接矩形の大きさにします（`mapMarkerPhoto()`が返す`size`。下に出す行先ラベルが画像に重ならないように）。

## 地図マーカーの画像サイズ

`.bus-marker-photo img`は**`width`/`height: 100%`で枠に収めてください。`max-width`/`max-height`では収まりません。** `leaflet.css`の`.leaflet-container .leaflet-marker-pane img { max-width: none !important; max-height: none !important; }`に打ち消され、画像が元の解像度（数百〜千px）のまま地図に描かれます。マーカーの大きさを変えるときは、CSSと`app.js`（`createBusIcon`）・`timetable.js`（`showLocationPopup`）の`iconSize`を揃えてください。

## 取得の失敗

`getPublicProfilesByCarIds()`は、20秒間隔でポーリングされる`/api/buses`のホットパスから呼ばれます。取得に失敗した場合は警告ログを出して**空のMap（全車両が未登録の扱い）を返し**、リアルタイム運行情報そのものは通常どおり返します（付加情報の失敗で運行情報を落とさないため）。
